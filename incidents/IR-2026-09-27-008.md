# IR-2026-09-27-008: Meterpreter C2 Beacon — T1071.001 (Command and Control)

## Summary

A Meterpreter reverse TCP payload (`beacon.exe`) was generated on Kali Linux,
transferred to Khonshu via HTTP, and executed. A full C2 session was established
from Khonshu (`10.71.19.2`) to Kali (`10.71.19.161:4444`). Wazuh detected the
attack chain through multiple built-in rules at Level 15 — the highest severity
in the lab — before the custom rule (100005) was in place. Post-session discovery
commands were also detected. Custom rule 100005 (T1071.001) was validated via
wazuh-logtest but not confirmed in live alerts due to a documented EID 3 shipping
gap (see Detection Gap below).

## Severity: Critical (simulated) | Built-in detection: Confirmed (Level 15)

## Detection Gap — Sysmon EID 3 Not Shipping

**Observation:** Sysmon EID 3 (NetworkConnect) was confirmed in Windows Event Viewer
for `beacon.exe → 10.71.19.161:4444` at both 10:20:34 and 10:51:00. However, zero
EID 3 events from Khonshu appeared in Wazuh during the same period.

**Root cause:** The Wazuh agent bookmark advances past EID 3 events during
`WazuhSvc` restarts on private-subnet connections (10.71.19.x). The ossec.conf
Sysmon localfile block has no EID filter — the issue is agent bookmark behaviour
under repeated service cycling, not configuration.

**Validation:** Custom rule 100005 was confirmed correct via `wazuh-logtest`:

```
Phase 3: Completed filtering (rules).
  id: '100005'
  level: '14'
  mitre.tactic: \['Command and Control']
  mitre.technique: \['Web Protocols']
\*\*Alert to be generated.
```

**Remediation recommendation:**

* Avoid cycling `WazuhSvc` during active simulation windows
* Increase agent `<queue\_size>` in ossec.conf to reduce event loss
* Consider a dedicated EID 3 test after agent stabilises for 10+ minutes

## Lessons Learned

* Level 15 alert (rule 92213) fired **before** custom C2 rule — built-in Sysmon
rules are effective at catching payload staging even without network telemetry
* Discovery command detection (net user, ipconfig via EID 1) shows that post-
exploitation activity is visible even when C2 channel telemetry is missing
* EID 3 shipping gap under service cycling is a real operational finding — in a
production SOC this would be a monitoring coverage gap requiring remediation
* FIM realtime monitoring of %TEMP% proved effective as a first-stage detection
layer independent of process or network telemetry
