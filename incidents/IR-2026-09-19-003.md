## Remediation

1. Task removed: `schtasks /delete /tn "WindowsUpdate" /f`
2. TaskCache\Tasks registry entry purged automatically on deletion
3. Audit policy verification — Task Scheduler logging must be enabled:

```
auditpol /set /subcategory:"Other Object Access Events" /success:enable /failure:enable
```

4. Monitor for legitimate tasks impersonating system names (WindowsUpdate, MicrosoftEdge, etc.)

---

## Lessons Learned

- `schtasks /ru SYSTEM` is a reliable privilege escalation primitive — any user in Administrators group can create SYSTEM-level tasks
- Task name `WindowsUpdate` is a common attacker choice to blend in with legitimate Windows tasks — name-based detection catches nothing; behavior (ONLOGON + SYSTEM + cmd.exe) is the signal
- FIM on `TaskCache\Tasks` catches this even without EID 4698 audit policy
- Sysmon EID 1 with `schtasks.exe` in CommandLine is the fastest detection vector — fires before the task can ever run
- Parent process `powershell.exe → schtasks.exe` is a high-confidence execution chain for T1053.005
